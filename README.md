# มิติ — FourView Studio / Local AI

## ภาพเดียว พร้อมลายผิว AI รอบตัว

เลือก "อัปโหลดภาพเดียว" → "ภาพเดียว · สร้าง 3D ทันที" → ตัวสร้าง "Hunyuan3D · รูปทรงและลายผิว AI รอบตัว" แล้วเปิด "สร้างลายผิว AI รอบตัว · Texture 2K" ตัวเลือกนี้ใช้ checkpoint สำหรับภาพเดียวโดยเฉพาะ (SingleImageEncoder) แทนการใส่ภาพเดียวลงโมเดล multiview จากนั้น Hunyuan3D-Paint สร้างลายผิวหกมุมโดยใช้แผนที่ normal/position ของโมเดล และอบเป็น UV texture 2048×2048 (ระดับละเอียด 4096×4096)

โมเดลทางการจาก `tencent/Hunyuan3D-2` ถูกตรึง revision `9cd649ba6913f7a852e3286bad86bfa9a2d83dcf` ดาวน์โหลดประมาณ 10 GB และตรวจ SHA-256 ของน้ำหนักทุกไฟล์ ติดตั้ง/ดาวน์โหลดต่อด้วย `powershell -ExecutionPolicy Bypass -File scripts/setup-single-image.ps1` เก็บ LICENSE/NOTICE และ installation.json ใน models/Hunyuan3D-2

การคำนวณ shape, ถอดผิว และ Paint ทำทีละโปรเซสเพื่อคืน VRAM ระหว่างขั้น ใช้ FP16 กับ CPU offload และคำนวณ classifier-free guidance ทีละชุดโดยเก็บทั้งหกมุมไว้ด้วยกัน การ raster/bake ใช้ CPU จึงไม่ต้องติดตั้ง CUDA compiler บน Windows ตัวสร้างผิวสีลด geometry เหลือประมาณ 100,000 สามเหลี่ยมเพื่อคลี่ UV โดยเก็บ shape.glb เต็มไว้สำหรับพรีวิว/ส่งออกรูปทรงสีเทา ระดับคุณภาพร่าง/สมดุล/ละเอียดใช้ Paint 16/24/30 steps ตามลำดับ

GLB รวม texture, OBJ ดาวน์โหลด ZIP พร้อม MTL/PNG, STL เก็บเฉพาะ geometry ภาพลายผิวแต่ละมุมเก็บเป็น paint-view-0.png ถึง paint-view-5.png คู่กับแผนที่ normal/position และ paint-result.json เพื่อให้ตรวจผลย้อนหลังได้ เลือกตัวสร้างใหม่แล้วกด "สร้างลายผิว AI ให้โมเดลเดิม" ได้ด้วย โดยบันทึกเป็นงานใหม่

ส่วนที่ภาพต้นฉบับมองไม่เห็นเป็นรายละเอียดที่ AI คาดเดา ผลลัพธ์อาจต่างจากต้นฉบับหรือมีรอยต่อ ขั้น Paint ใช้ภาพอ้างอิงตรงๆ โดยไม่ได้เรียกโมเดล Delight แยก ลดจำนวนโมเดลที่ต้องโหลด โหมด "แบบเดิม · ฉายสีจากภาพ" และภาพสี่มุมยังใช้ได้

แหล่งที่มา: [Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2), [น้ำหนักทางการ](https://huggingface.co/tencent/Hunyuan3D-2)

## ภาพด้านข้างและผิวสมมาตร

เปิด "ภาพด้านข้าง · ใช้ตาและลายต้นฉบับทั้งสองฝั่ง (สมมาตร)" ก่อนสร้างโมเดลหรือกดทำลายผิวให้โมเดลเดิม ระบบสะท้อนพิกัดผิวตามแกนความลึก Z ของโมเดลภาพเดียว โดยใช้กล้อง reference เดิม จึงอ่านตา เกราะ และผลึกจากภาพอัปโหลดทั้งสองฝั่ง ไม่กลับตำแหน่งหัวกับหางในภาพ ส่วนที่กล้องทั้งสองด้านไม่เห็นยังใช้ Paint และตรวจการบังผิวโดยยอมความคลาดของรูปทรงเล็กน้อย โหมดนี้ทำให้ลายผิวสมมาตร โดยไม่ได้บังคับให้ geometry สมมาตรทั้งตัว หากตรวจพบช่องปากด้านข้างที่ชัดเจนและแนวช่องปากคลาดไม่เกิน 8% ของความสูงภาพ จะขยับเฉพาะบริเวณปากอย่างนุ่มนวล พร้อมเก็บ shape-before-mouth.glb และ mouth-alignment.json กล้องหัวใช้ yaw/pitch 0 แยกจากกล้องลำตัว เพื่อให้ฟันและขอบปากไม่เลื่อนตามการจัดแนวหาง ใช้สำหรับภาพด้านข้างของวัตถุที่ต้องการลายสองฝั่งเหมือนกัน ค่าบันทึกเป็น reference_symmetry ใน job.json และแกน/ระนาบใน reference-calibration.json

## ความคมและการรักษาภาพต้นฉบับ

ใช้ inverse UV sampling อ่านสีให้ทุก texel แทนการ splat จากภาพ 512 แล้วเติมช่องว่างด้วยสี vertices ซึ่งทำให้เกิดเม็ด ผิวด้านที่มองเห็นใช้ภาพอัปโหลดผ่านกล้องที่จัดแนวและตรวจ depth; ส่วนที่ถูกบังและด้านอื่นใช้ภาพ Paint ทั้งหกมุม ไม่เกลี่ยพิกเซลที่มีข้อมูลแล้ว Padding เติมเฉพาะ texel ที่ว่าง และวัสดุใช้ตัวคูณสีขาวเพื่อรักษาสี texture ผลแต่ละงานเก็บ reference-coverage.png กับ reference-calibration.json ระดับละเอียดเพิ่มขนาด atlas เป็น 4K แต่ภาพ AI แต่ละมุมยัง 512 และความคมจริงของด้านอัปโหลดขึ้นกับภาพต้นฉบับและรูปทรงที่สร้าง

## การแก้สี GLB และหน้าพรีวิว (7 ตุลาคม 2026)

แก้การส่งออก vertex color: สีจากภาพเป็น sRGB แต่ glTF ต้องใช้ linear RGB จึงแปลง RGB เป็น float32 ก่อนเขียน GLB โดยคง alpha เดิมไว้ ไม่ลดความแม่นยำเป็น linear 8-bit และไม่เปลี่ยนสีของ OBJ หรือภาพ texture งาน GLB เก่าที่มี `vertex_color` จะถูกแก้ระหว่างดาวน์โหลด/แสดงผลโดยไม่เขียนทับต้นฉบับ พรีวิวรองรับไฟล์เก่าและใหม่โดยตรวจ marker ใน asset extras เพื่อไม่แปลงสีซ้ำ

ขยายพื้นที่พรีวิว ปรับกล้องเริ่มต้นให้ใกล้ด้านหน้า เพิ่มปุ่มสลับพื้นหลังและเส้นกริด การแก้นี้ไม่เปลี่ยน geometry และไม่สร้างรายละเอียดด้านหลังใหม่: โหมดภาพเดียวยังเติมด้านที่มองไม่เห็นด้วยสีประมาณจากภาพเดิม

ทดสอบด้วย `python -m unittest backend.test_color_export -v` และ `npm run build`

อัปโหลดภาพหน้า/ขวา/หลัง/ซ้ายแล้วสร้างผิวโมเดลด้วย Hunyuan3D-2mv บน GPU ในเครื่อง รองรับ OBJ, GLB, STL และแสดงโมเดลผ่าน Three.js UI ใช้ HeroUI

## วิธีสร้างโมเดลแบบเดิมจากสี่มุม (ข้อมูลรุ่นก่อน)

1. เลือกภาพหน้า ขวา หลัง ซ้าย ของวัตถุเดียวกัน ควรเป็นมุมตรง ไม่ถูกตัด และสัดส่วนของวัตถุสอดคล้องกัน
2. เริ่มที่ระดับร่าง 256 ซึ่งใช้ diffusion 25 steps สำหรับ GPU VRAM 8 GB แล้วเพิ่มเป็น 384/512 เมื่อหน่วยความจำเพียงพอ
3. เปิด "รายละเอียดผิวจากภาพต้นฉบับ · Texture 4K" ถ้าต้องการลายจากภาพทั้งสี่ด้าน
4. กดสร้างโมเดล ดูความคืบหน้าจริงจากขั้น diffusion และรอการถอดผิวสามเหลี่ยม
5. ลากเพื่อหมุน เลื่อนล้อเมาส์เพื่อซูม แล้วส่งออก GLB/OBJ/STL

หากงานหยุดหลังคำนวณรูปทรงครบแล้ว กด "สร้างต่อจากงานเดิม" เพื่อถอดผิวต่อจาก shape-latents.pt ที่บันทึกไว้ ตัวถอดผิวทำงานในอีกโปรเซสและโหลดเฉพาะ VAE หลังคืนหน่วยความจำของตัวสร้างรูปทรงแล้ว

GLB เก็บ UV และภาพผิวจาก reference atlas 4096×4096 พร้อมในไฟล์เดียว OBJ รุ่นที่มี texture ดาวน์โหลดเป็น ZIP พร้อม MTL/PNG ให้แตกไฟล์ไว้ด้วยกันก่อนนำเข้า ส่วน STL เก็บเฉพาะรูปทรง ระบบจัดแนวมุมภาพจาก silhouette และเลือกภาพตามทิศผิวและการถูกบัง แทนการเฉลี่ยสีหลายภาพลงทุกจุด ภาพแต่ละมุมอยู่ในช่อง 2048×2048 โดยรายละเอียดจริงขึ้นอยู่กับความละเอียดต้นฉบับ การวางผิวเป็นการประมาณแบบ orthographic ยังอาจมีรอยต่อ/ตำแหน่งคลาดเคลื่อน และไม่สร้างรายละเอียดที่ไม่มีในภาพ

กด "เพิ่มรายละเอียดผิวโมเดลเดิม" เพื่อทำ texture ใหม่จากรูปทรงที่สร้างเสร็จแล้ว โดยระบบบันทึกเป็นงานใหม่และเก็บงานเก่าไว้ ไม่ต้องคำนวณ diffusion ซ้ำ พรีวิวใช้วัสดุไม่รับแสงและเงาเพื่อแสดงสีจากภาพตรงๆ

การเลือกมุมภาพใช้ normals ที่กรองตามระยะในพื้นที่ 3D และลดการสลับแหล่งภาพระหว่างสามเหลี่ยมที่ติดกัน ใช้การฉายภาพแบบ affine เดียวต่อมุมภาพ โดยไม่บิดความกว้างตามแถวเพื่อหลีกเลี่ยงลายเกราะเป็นคลื่น เลือก "รูปทรงสีเทา" ในหน้าพรีวิวเพื่อดูรูปทรงโดยไม่มีลายผิว โหมดนี้ใช้แสงสตูดิโอเพื่อให้เห็นผิวโค้ง ส่วน "สีภาพ" ยังคงแสดงสีโดยไม่รับเงา

ตรวจการสร้างจริงบน RTX 5060 Laptop 8 GB / RAM 16 GB ด้วยภาพตัวละคร 4 มุมที่ระดับ 512, diffusion 50 steps: สร้างครบผ่านหน้าแอปใน 278 วินาที ได้ 732,744 vertices และ 1,465,451 triangles หลังเก็บผิวซ้ำ เวลาและจำนวนผิวขึ้นอยู่กับรูปและโปรแกรมอื่นที่เปิดอยู่

## การอบผิวสีแบบต่อเนื่อง

รุ่น v2 ลดภาพซ้อนในส่วนบนของรูปทรง: ช่วงความสูง 64–72% เปลี่ยนจากผสมหลายภาพเป็นใช้ภาพหลักต่อฝั่งของหัว (ซ้าย/ขวา และกลางหน้า/หลัง) เพื่อหลีกเลี่ยงตาและฟันซ้อนจากภาพวาดต่างมุม จัดแนวหัวด้วยกรอบภาพส่วนบน 28% แยกจากกรอบทั้งตัวที่รวมหาง ส่วนคอและลำตัวยังเกลี่ยสีต่อเนื่อง นี่เป็น heuristic สำหรับตัวละครหัวอยู่ด้านบน ไม่ใช่ตัวตรวจจับหัวหรือการฝึก AI เพิ่ม และไม่แก้ขากรรไกรที่ผิดในรูปทรงจริง

ตัวทำผิวรุ่นปัจจุบันคลี่ UV ด้วย xatlas และอบสี 4096×4096 ลง atlas เดียว คำนวณน้ำหนักมุมภาพตามทิศผิวและการถูกบังที่แต่ละพิกเซล เกลี่ยการเปลี่ยนแหล่งภาพต่อเนื่องแทนการเลือกภาพแบบตัดขาดตามสามเหลี่ยม และเติมสีขอบ UV เพื่อป้องกันเส้นดำเวลาแสดงผิว กด "เพิ่มรายละเอียดผิวโมเดลเดิม" เพื่อใช้กับงานเก่า ระบบเก็บเป็นผลงานใหม่และไม่เปลี่ยนรูปทรงต้นฉบับ

นี่เป็นการแก้ขั้นตอน texture baking ไม่ได้ fine-tune น้ำหนัก AI ภาพอ้างอิงที่วาดแยกมุมและมีลายหรือสัดส่วนต่างกันยังอาจทำให้ลายซ้อน/คลาดเคลื่อนในช่วงเกลี่ยสีได้ จึงไม่รับประกันว่าการอบสีจะสร้างรายละเอียดที่ต่อกันถูกต้องทุกส่วนจากภาพที่ไม่สอดคล้องกัน

## ภาพเดียว · สร้าง 3D ทันที

เลือก "อัปโหลดภาพเดียว" (รูปแบบเริ่มต้น "ภาพเดียว · สร้าง 3D ทันที") เพิ่มภาพตัวละครหรือวัตถุภาพเดียวแล้วกด "สร้างโมเดล 3D" ระบบแยกพื้นหลัง ส่งภาพเข้า Hunyuan3D-2mv ในช่องด้านหน้าช่องเดียว แล้วถอดผิวตามปกติ ไม่เรียก Wonder3D และไม่ต้องเตรียมภาพหลายมุม ปุ่มถังขยะบนภาพใช้ลบภาพที่เลือก

ระหว่างสร้าง หน้าต่างแสดงผลแสดงกลุ่มจุดตามเงาร่างของภาพและแถบความคืบหน้าเดียว แถบเดินตามขั้น diffusion ส่วนขั้นอื่นแสดงเป็นแถบเคลื่อนไหว กลุ่มจุดเป็นภาพประกอบระหว่างรอ ไม่ใช่รูปทรงที่ AI กำลังคำนวณ

สีของโหมดนี้ใช้ colorize_single ใน backend/aligned_vertex.py: ด้านที่ภาพมองเห็นฉายสีคมชัดจากภาพต้นฉบับ ส่วนด้านที่ภาพมองไม่เห็น (ด้านหลังและส่วนที่ถูกบัง) เติมด้วยสีจากภาพเดียวกันที่เบลอแล้วฉายทะลุโมเดล จึงได้โทนสีใกล้เคียงแต่ไม่มีลวดลายจริงของด้านหลัง ไม่ใช่การเจน texture ด้วย AI รูปทรงด้านหลังเป็นการคาดเดาของโมเดลจากภาพเดียว เมนูจัดแนวภาพมีเฉพาะด้านหน้า ถ้าต้องการลายด้านหลังให้ใช้ภาพ 4 มุมหรือรูปแบบ "ภาพด้านหน้าเดียว · AI สร้างมุมเพิ่มก่อน"

## อัปโหลดภาพเดียวแบบรวม 4 มุม

เลือก "อัปโหลดภาพเดียว" และรูปแบบ "ภาพรวม 4 มุมในไฟล์เดียว (2×2)" อัปโหลดไฟล์เดียวแล้วกด "สร้างโมเดล 3D" ระบบแบ่งภาพตามกึ่งกลาง: บนซ้าย = หน้า, บนขวา = ซ้าย (จมูกหันไปทางซ้าย), ล่างซ้าย = ขวา (จมูกหันไปทางขวา), ล่างขวา = หลัง แล้วส่งเข้า Hunyuan3D-2mv โดยตรง ไม่ต้องเจนภาพเพิ่มด้วย Wonder3D ภาพต้นฉบับเก็บเป็น source.png และแสดงในช่องอัปโหลดเดียวเมื่อเปิดผลงานอีกครั้ง ภาพต้องจัดมุมเป็นตาราง 2×2 ตามลำดับนี้

ถ้ามีภาพด้านหน้าเพียงมุมเดียว เลือกรูปแบบ "ภาพด้านหน้าเดียว · AI สร้างมุมเพิ่มก่อน" เพื่อใช้ Wonder3D ตามขั้นตอนด้านล่าง

## การใช้ภาพหน้าเดียว

ขั้นตอนที่ 1 เลือก "อัปโหลดภาพเดียว" และรูปแบบ "ภาพด้านหน้าเดียว · AI สร้างมุมเพิ่มก่อน" อัปโหลดด้านหน้าครบทั้งตัว แล้วกด "เจน 3 มุมและสร้าง 3D" ระบบใช้ Wonder3D ในเครื่องสร้างซ้าย ขวา และหลัง ก่อนส่งทั้งสี่ภาพต่อให้ Hunyuan3D-2mv ภาพที่ระบบสร้างแสดงป้าย AI และบันทึกพร้อมงานบน D โดยภาพหน้าเดิมยังคงเป็นต้นฉบับ

Wonder3D สร้างมุมภาพขนาด 256×256 การเจนคือการคาดเดาส่วนที่มองไม่เห็น จึงอาจมีรูปทรง ลาย หรือสัดส่วนต่างจากต้นฉบับ ถ้ามีภาพสี่มุมที่สอดคล้องกันอยู่แล้วให้เลือก "อัปโหลด 4 มุม" ได้ตามเดิม

ติดตั้งเพิ่มเติมด้วย `powershell -ExecutionPolicy Bypass -File scripts/setup-view-generator.ps1` หลังติดตั้ง local AI หลัก ตัวติดตั้งโหลด checkpoint และ source ที่ตรึง revision ไว้ลง models/Wonder3D และ vendor/Wonder3D-pipeline ใช้ Diffusers 0.19.3 ใน vendor/Wonder3D-deps แยกจากตัวสร้างรูปทรง และรันแต่ละตัวตามลำดับเพื่อคืน VRAM ก่อนเริ่ม 3D [Wonder3D source](https://github.com/xxlong0/Wonder3D)

## โหมดทางเลือก: สีแบบดั้งเดิม
ใช้ project_vertex_colors ใน backend/server.py เหมือนรุ่นแรก ฉายสีจากภาพสี่มุมลง vertices ของรูปทรงเต็ม โดยไม่เรียก texture_from_references / UV bake / การจัดแนวหัว / การลดสามเหลี่ยม GLB เก็บ vertex colors และ STL เก็บรูปทรง การเพิ่มสีไม่ใช่การเทรน AI รุ่น UV เก็บสำรองไว้ใน backups/before-classic-restore แต่ไม่ได้เป็นเส้นทางสร้างงานปัจจุบัน

## จัดแนวภาพก่อนฉายสี
เพิ่ม backend/aligned_vertex.py: จัดมุมกล้อง yaw ใกล้เคียง ±15 องศาและ pitch ±10 องศาด้วย silhouette แบบคร่าว ๆ แล้วตรวจ z-buffer จากสามเหลี่ยมจริงก่อนฉายสีบน vertices ไม่คลี่ UV ไม่บิดหรือปรับจำนวนสามเหลี่ยม เปิดเมนูจัดแนวภาพกับโมเดลเพื่อปรับ x/y ±20%, scale 0.5–1.5 และ yaw ±30 องศาแต่ละด้าน กดใส่สีโมเดลเดิมเพื่อทำสีใหม่ ผลมุมที่ใช้เก็บใน color-alignment.json ค่าปรับเก็บใน job.json วิธีนี้ยังไม่ตรวจจุดใบหน้าและไม่รับประกันภาพต่างสัดส่วนจะตรงกันทุกส่วน

## พรีวิวภาพซ้อนสำหรับจัดแนว
POST /api/jobs/{id}/alignment-preview เรนเดอร์ shape.glb จริงด้วยกล้องเดียวกับการฉายสี ขนาด 512px แล้วซ้อนภาพ cutout: ฟ้า=ขอบโมเดล ชมพู=ขอบอ้างอิง ม่วง=ขอบทับกัน ปรับ opacity 0 เพื่อดูรูปทรงล้วนและขยาย 1–3x ได้ ตัวเลื่อนอัปเดตพรีวิวหลังหยุดเลื่อนประมาณ 450ms (เวลารวมขึ้นกับ CPU) ไม่ทำสีทั้งโมเดลจนกดนำค่าไปใส่สีโมเดลเดิม มุมอัตโนมัติใช้ค่าที่บันทึกใน color-alignment.json ถ้ายังไม่มีจะแสดงคำบอกว่าใช้มุมมาตรฐาน ขอบตรงกันไม่ยืนยันว่าตา/ปากและรายละเอียดทุกส่วนตรงกัน
